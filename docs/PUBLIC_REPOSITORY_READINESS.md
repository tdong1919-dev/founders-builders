# Public repository readiness

**Preparation only. Visibility remains private as of November 12, 2026.** The owner requested preparation for public after review. This is not a completed exposure audit or authorization to change visibility.

Public source exposes more than today's README. It does not grant database access, approve beta accounts, or create an open-source license.

## Exposure checklist

- [ ] Inventory tracked files, full reachable history, branches/tags, releases, attachments, workflow logs/artifacts, LFS objects if present, and issue/PR discussions that may become public.
- [ ] Scan for secrets and manually review findings: passwords, server/API keys, agent credentials, signed links, email tokens, and deployment configuration. Rotate exposed secrets where needed. Removing a current file does not remove history/copies.
- [ ] Review participant data, fixtures, screenshots/recordings, support evidence, backup references, logs, and personal contacts. A public support address is intentional; participant accounts/private storage links are not automatically publishable.
- [ ] Confirm no backup archive, recovery key, production dump, local database, or private contribution is tracked. Encryption alone does not justify public backups.
- [ ] Review older setup instructions and deferred/manual flow descriptions. Direct readers to the new documentation index.
- [ ] Choose the source license; review third-party code/assets, fonts/media, and attribution. Public does not automatically mean open source.
- [ ] Verify the beta link, safe fictional example, documentation links, and roadmap claims. Distinguish dated evidence from fresh checks.
- [ ] Confirm source publication changes no backend authorization, public-field projection, signup policy, or agent limit.
- [ ] Ensure website deployments use reviewed assets, not the full source tree.
- [ ] Record findings/remediation without copying secrets or private evidence into public reports. Plan any history cleanup separately; never silently rewrite shared history.
- [ ] Obtain explicit owner approval for the final visibility change.

## Required review record

Record date, reviewer, refs/coverage, scan tools/versions, manual scope, redacted findings, remediation/rotation status, licensing decision, and exclusions. A clean scan is not a guarantee of no sensitive information.

This documentation update improves readability and the roadmap only. It changes no website behavior, production service, permission, notification setting, repository visibility, or source license.
