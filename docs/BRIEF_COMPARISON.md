# Turning feedback into a controlled comparison

brief-experiment.html is linked from the orchestrator owner report. It compares an incomplete and a clearer brief for the same fictional 45-minute task, using the same normalized builder/founder permissions, message budget and task-time limit. Permissions are snapshotted once before either arm runs; user changes abort the current comparison. No mode or permission is silently broadened to achieve a better result.

The server accepts a bounded initial metadata.brief variant (needs-clarification or clear), binds it into the signed snapshot and reports it in response metadata. A clearer approved brief can return a proposal on the first inquiry; the incomplete brief asks a scope question first. The builder client validates the expected variant and phase, sending a clarification only if needed. Continuation requests cannot replace the signed variant or policies. Time restrictions are enforced before returning a proposal for either variant. Follow-up clarification permission still applies whenever a follow-up is attempted. Asking for an already approved complete brief is not a forbidden clarification.

Both arms stop at proposal-ready-for-review. Neither calls approve/decline, prepares an introduction, accepts terms, contacts a real person, reads private data or writes a database. The comparison is two deterministic rule-based fixtures over real HTTP, not an experiment on real people, a model benchmark or proof of causal ecosystem improvement. Timing is deliberately not compared because runs are sequential and not suitable for latency inference.

The report shows observed processed messages, clarification responses, blocked attempts, HTTP attempts, policies and outcomes for each arm. Only successful returned exchanges count as observed processed messages; a failed response leaves server processing uncertain. An improvement difference is reported only if both arms reach review. Policy stops and request failures stay distinct. No successful comparison is shown after an aborted/partial run. Displayed results use readable labels; the table scrolls within a bounded region on narrow screens. Controller tests do not establish rendered mobile behavior.

Reports contain only fictional aggregates and policy settings, with no message bodies, names, task IDs, continuation tokens or signing keys. Traces are rendered literally. Results stay in page memory; explicit copying is available. Changing controls, stopping or navigating away aborts pending work and prevents late messages/results/copy notices from populating a new comparison. Clear/reset is not server-side revocation of already issued snapshots.

Default result in this scripted fixture: incomplete brief requires two processed messages (inquiry + clarification), clearer brief requires one (inquiry), both reaching review with identical permissions. A one-message budget can stop the incomplete arm while the clearer arm reaches review without changing that budget. A 30-minute task limit stops both arms. These findings demonstrate the feedback → content change → retest mechanism; they do not verify real collaboration success or justify weaker boundaries.
