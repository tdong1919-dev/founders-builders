# A2A fictional protocol sandbox

The builder agent in a2a-sandbox-client.js discovers the server founder agent at /.well-known/agent-card.json, chooses the advertised same-origin A2A 1.0 JSON-RPC interface, and sends actual HTTP SendMessage requests. Both agents are deterministic rule-based programs with no model calls. The browser automatically sends an inquiry and a fixed clarification, then stops. The UI shows the two roles, server responses and protocol states; it offers Prepare fictional introduction or Stop exchange. The final server response either includes a draft artifact (completed) or stops without one (canceled). No real founder is contacted.

The implementation follows the [A2A 1.0 specification](https://a2a-protocol.org/v1.0.0/specification/) for the implemented message envelope, roles, parts, version header, task/context IDs, input-required states and artifact structure. It is a **SendMessage subset**, not a certified or complete A2A implementation. It omits GetTask/ListTasks/CancelTask, streaming, push, durable task history and general-purpose agent onboarding. The UI stop decision is a scenario-specific message that produces a canceled state, not the A2A CancelTask operation. Unsupported methods fail explicitly.

## Scope and safety

Only four fixed structured actions are accepted. The server reconstructs fictional dialogue rather than echoing arbitrary input. Unknown personal fields are not returned. No prompts, URLs, files, real offers, profiles or private projects are accepted as task content. Requests are limited to 8 KiB; response IDs, roles, same-origin endpoints and declared A2A version are checked. Cross-origin browser requests are denied. The server performs no outbound calls and uses no database.

Short-lived HMAC-signed continuation snapshots carry a generated task/context, phase and ten-minute expiry. They remain in page memory and request metadata, never URLs or the rendered transcript. FB_A2A_SANDBOX_SECRET is configured as a Sites server-only secret, absent from source and browser assets. Signatures prevent phase/task tampering; they do **not** create durable state, per-run revocation, one-time consumption or replay prevention. Replaying an old valid snapshot can fork a fictional run. This is intentionally limited to side-effect-free sample drafts and is not suitable for live agreements or messaging. Reset/reload clears the local run but cannot revoke copied snapshots. Tokens are not proof of a human identity.

Decision buttons demonstrate a human pause in the supplied client. A custom client could submit an approve action itself; this prototype does not verify human presence or owner's delegated authority. Production requires authenticated identities, scoped revocable delegation, a server-side approval record, recipient controls, audit history and rate limits. Task completion here means a sample draft was prepared, not a contribution completed or a contract agreed. All responses keep real-message, terms-accepted and portfolio-permission flags false.

Sites owner-only access is preserved around all hosted routes. The runtime depends on that platform boundary, not on a new public API or OAuth implementation. External agents cannot use a private site without separately authorized service access. No service credential is published. Supabase remains disabled; the private review copy has no live Apps Script URL. The existing repository backend configuration is unchanged.

## Review packaging

The review site transitions from static hosting to one dependency-free Worker, preserving the same project ID and private audience. sandbox/build-review-worker.mjs embeds an allowlist of public HTML/JS/CSS/JSON/SVG assets, rejects live Sheets URLs or enabled Supabase, and emits dist/server/index.js plus the unchanged-identity manifest. The Worker routes card/RPC requests to the server and serves other pages as before. Runtime secrets are not in the build. This is a review deployment, with no main-branch merge, database binding, paid model runtime or live backend rollout.

Browser-rendered desktop/mobile layout and private-site interactive sign-in remain separate verification steps. Run `node --test tests/*.test.cjs` with permission to bind a loopback test port. sandbox/verify-hosted.mjs can check a deployed private sandbox using an in-memory platform service credential through stdin; do not paste credentials into scripts, URLs or Git.
