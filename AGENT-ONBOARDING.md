# Permission-aware agent onboarding

Choose one contribution, choose a mission preset, review the individual actions and limits, then explicitly authorize the grant. Read and advise starts with read-only access. Other presets select only actions available to the current founder/builder at the current stage. A preset is setup intent, not a saved autonomous mission or a new server capability. The exact grant remains the authority. Editing a preset, action or limit clears consent.

After issuing a credential, Test this connection makes one fixed-endpoint agentContext request using that credential. It validates task scope, expiry and remaining requests without consuming the grant's action budget or submitting messages, applications, agreements or work. Failure responses are generic. There are no retries, polling, browser persistence or arbitrary destinations. Results are discarded if the account/view changes. The credential remains shown once under the existing behavior; refresh/sign-out clears it. The test button is one-use.

This verifies platform access, not that an external host has successfully connected. Transfer a limited credential only through the chosen host's secure credential settings. ChatGPT public discovery remains separate from private owner authorization. No background agent worker is created.

Human agreement confirmation, permissions, reviews and portfolio credit remain human decisions. Existing immediate revocation and activity records apply. No new backend, database schema, authorization rules or paid infrastructure.

## Acceptance checklist

1. In founder and builder accounts, select a contribution and open Agent access. Confirm each preset only selects actions available to that role/stage.
2. Check the summary. Authorize, then change a limit: consent must clear.
3. Issue a deliberately limited credential and run the connection test. Confirm there are no new applications/messages/work and no request-budget consumption.
4. Test the external host separately; do not treat the browser test as host acceptance. Revoke in the owner control center and confirm future access is denied.
5. Verify desktop/mobile layout and session clearing. Visual acceptance remains pending while local browser use is disabled.

Public discovery acceptance from PR #38 also remains pending: explicitly publish a safe card in each account, confirm its approved projection, pause/withdraw and verify future discovery excludes it. Automated tests cover these server boundaries; no real public cards or credentials were created by this release.
