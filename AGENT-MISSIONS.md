# Your agent missions

Open Your control center → Agent missions. Each contribution with owner-issued agent access has one card: a short contribution goal, recorded status, latest valid recorded update, and one primary action. Related grants are grouped, rather than shown as duplicate missions. Questions needing a person come first.

Statuses:
- Needs you: an owner-private agent question or a human collaboration step. Opens the exact question/contribution.
- Waiting: the existing collaboration next step belongs to someone else. Shows what is awaited.
- Ready for your agent: a grant is active, but no current external work is confirmed. This never claims an external worker is running.
- Access stopped: all grants are revoked, expired or exhausted, with no higher-priority collaboration step. Review permissions opens onboarding; it does not issue or renew a grant.
- Finished / Ended: all recorded contributions are closed/cancelled and no human next step or unanswered agent question remains. A missing review still needs the owner.

Permissions and controls are collapsed. They show actions, remaining requests, task time limit and expiry. Stop this access calls existing revocation only on explicit click. Review new access opens the existing task-specific approval flow with fresh consent. Existing human work can continue with agent access stopped. Pausing new applications does not stop existing work or revoke access.

The goal is the authorized task deliverable (or confirmed contribution deliverable/title fallback), not an independently saved mission promise. Long goals are shortened only in the card. There is no new worker, autonomous scheduling, agent heartbeat, polling, cross-owner discovery or permission expansion.

Updates are actual owner-agent question or participant contribution timestamps. The fallback is explicitly labeled Access created; future/invalid dates are ignored. Opening this view does not fetch activity, write state, reset timing or consume grant budget. Refresh saved progress reloads records. Sign-out clears cards. Message bodies and credentials are not copied into summaries.

Automated coverage includes owner isolation, grouping, state priority, exact navigation, waiting and review handoffs, stopped access, future/unknown timestamps, unchanged paused-work permissions, explicit stop and approval-only renewal.
